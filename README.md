# proof-of-work

Быстрый трекер рабочего времени для Wayland (niri) с автоматическими скриншотами рабочего окна и экранным индикатором статуса.

## Особенности
* **Захват выделенного рабочего пространства (workspace)**: В niri можно выделить отдельный воркспейс под работу (`WORKTRACK_WORKSPACE="work"`). Трекер снимает **только** этот воркспейс! Даже если на основном мониторе или на других воркспейсах открыты личные приложения (Telegram, браузер, менеджер паролей), они никогда не попадут на скриншот.
* **Захват выбранного дисплея**: Если воркспейс не задан, снимает указанный в настройках монитор (`WORKTRACK_OUTPUT`) или активный монитор с фокусом.
* **Защита конфиденциальности (Blacklist приложений)**: Список запрещённых приложений (`WORKTRACK_BLOCKED_APPS`) автоматически закрашивается сплошным чёрным цветом, если окно попадает на скриншот.
* **Экранный индикатор с часами, обратным таймером и учётом рабочего времени (Wayland)**: Компактная полупрозрачная плашка в правом верхнем углу экрана, на котором производится захват, с текущим системным временем, живым обратным отсчётом до следующего снимка и оставшимся временем до конца 8-часового рабочего дня (клики проходят сквозь неё):
  * `20:30 | 0:45 | 7h 45m 🔴` — запись активна: реальное системное время, отсчёт до кадра и остаток нормы
  * `20:30 | PAUSE | 7h 45m 🟡` — трекер на паузе
  * `20:30 | 0:45 | 0h 00m 🟢` — дневная норма выполнена (зелёная индикация), при переработке отображается `+0h 15m`
  * **Память смен**: программа автоматически учитывает ранее отработанные сегодня смены (по архивам и скриншотам за текущий день) и вычитает их из дневной нормы
* **Оптимизированный формат JPG**: Снимки сохраняются в сжатом JPG (качество 60 по умолчанию, размер снимка ~500 КБ даже на 4K-мониторах), благодаря чему текст в коде и терминале остаётся чётким и читаемым, а суточный архив весит всего ~150–250 МБ.
* **Штамп даты и времени без фона**: На каждый снимок автоматически наносится аккуратный таймштамп в левом нижнем углу с теневой обводкой для читаемости без загромождения тёмным фоновым прямоугольником.
* **Архивация и безопасная выгрузка на FTP**: Сборка в `.tar.gz` при завершении смены и отдельная команда `worktrack upload` с подтверждением (`[y/N]`), подробным отчётом по фактически отработанному за день времени и выгрузкой на FTP/FTPS (или через `WORKTRACK_UPLOAD_CMD`).

## Команды управления

```bash
worktrack start       # Запустить трекер в фоне (демон + экранный индикатор)
worktrack shot        # Сделать тестовый снимок прямо сейчас
worktrack pause       # Поставить на паузу (индикатор станет жёлтым)
worktrack resume      # Снять с паузы (индикатор станет красным, снимок сразу)
worktrack reset       # Сбросить рабочую смену и таймер за сегодня (с подтверждением [y/N])
worktrack reset -y    # Сбросить рабочую смену без подтверждения
worktrack status      # Текущее состояние и количество снимков за сегодня
worktrack workspaces  # Список всех воркспейсов niri и открытых на них окон
worktrack outputs     # Список подключённых мониторов (для WORKTRACK_OUTPUT)
worktrack pack        # Принудительно упаковать день в .tar.gz (без отправки)
worktrack upload      # Отправить архив за сегодня на FTP (с подтверждением и отчётом по отработанным часам)
worktrack upload -y   # Отправить архив на FTP сразу без подтверждения
worktrack stop        # Завершить трекер и упаковать день в .tar.gz (без авто-отправки)
worktrack update      # Обновить бинарник до последней версии с GitHub Releases без компиляции
```

## Быстрая установка готового бинарника (без сборки)

Чтобы **не компилировать** программу из исходников и не тратить время и ресурсы процессора, установите готовый бинарник одной командой:

```bash
curl -fsSL https://raw.githubusercontent.com/IVKLD/proof-of-work/main/install.sh | bash
```

Либо из склонированного репозитория:
```bash
./install.sh
```

Установщик:
* Скачивает свежий оптимизированный бинарник для Linux x86_64 с GitHub Releases.
* Копирует его в `~/.local/bin/worktrack`.
* Автоматически настраивает автодополнение команд для `bash`, `zsh` и `fish`.
* Создаёт шаблон конфигурации `~/.config/worktrack.env` (если файл ещё не создан).
* Установка занимает **всего 1–2 секунды**.

Для последующего обновления трекера на новую версию достаточно выполнить:
```bash
worktrack update
```

## Конфигурация ПО (`~/.config/worktrack.env`)

Параметры считываются из файла `~/.config/worktrack.env` (или системных переменных окружения):

```bash
# Каталог для логов, скриншотов и архивов (по умолчанию: ~/worklog):
WORKTRACK_DIR="$HOME/worklog"

# Интервал между автоматическими снимками в секундах (по умолчанию: 60):
WORKTRACK_INTERVAL=60

# Дневная норма рабочего времени в часах (по умолчанию 8):
# Трекер вычитает ранее отработанные сегодня смены и ведёт обратный отсчёт
WORKTRACK_DAILY_HOURS=8

# Фиксированное время начала смены (например "09:00", "12:00").
# Если не задано — определяется автоматически по первому запуску трекера сегодня:
# WORKTRACK_START_TIME="09:00"

# Выбор конкретного рабочего пространства (workspace) в niri.
# Трекер будет снимать ТОЛЬКО этот воркспейс, даже если на других экранах
# или в фоне открыты личные приложения (Telegram, браузер и т.д.):
# WORKTRACK_WORKSPACE="work"

# Привязка к конкретному экрану (например "DP-1" или "DP-2").
# Используется, если WORKTRACK_WORKSPACE не задан:
# WORKTRACK_OUTPUT="DP-1"

# Список запрещённых приложений через запятую (по app_id или названию окна).
# Окна этих приложений будут закрашены сплошным чёрным цветом на скриншотах:
WORKTRACK_BLOCKED_APPS="telegram,keepassxc,discord"

# Масштабирование плашки индикатора (HiDPI).
# Автоматически: 2.2x на 4K (3840+), 1.4x на QHD (2560+), 1.0x на 1080p.
# Можно принудительно задать свой множитель:
# WORKTRACK_SCALE=2.2

# Формат скриншотов ("jpg" или "png", по умолчанию "jpg"):
WORKTRACK_FORMAT="jpg"

# Качество JPG от 10 до 100 (по умолчанию 60):
WORKTRACK_JPEG_QUALITY=60

# Максимальная ширина скриншота (по умолчанию 1920).
# Снимки с 4K/QHD экранов аккуратно масштабируются до Full HD (1920x1080),
# благодаря чему каждый снимок весит ~450–500 КБ, а текст в терминале и IDE остаётся полностью читаемым.
# Для сохранения в исходном разрешении монитора укажите 0 или "full":
WORKTRACK_MAX_WIDTH=1920

# Настройки прямого FTP для автоматической отправки архивов дня:
# WORKTRACK_FTP_HOST="ftp.example.com"
# WORKTRACK_FTP_PORT=21
# WORKTRACK_FTP_USER="username"
# WORKTRACK_FTP_PASS="password"
# WORKTRACK_FTP_DIR="/screenshots/"
# WORKTRACK_FTP_SECURE=false

# Либо произвольная команда для отправки архива в конце рабочего дня.
# Токен {file} автоматически заменяется на полный путь к созданному .tar.gz:
# WORKTRACK_UPLOAD_CMD='curl -fsS -F "file=@{file}" https://example.com/api/upload'
# WORKTRACK_UPLOAD_CMD='rsync -avz "{file}" user@remote:/backups/worklog/'
```

### Параметры конфигурации

| Переменная | Значение по умолчанию | Описание |
| :--- | :--- | :--- |
| `WORKTRACK_DIR` | `~/worklog` | Каталог, в который складываются папки по датам (`YYYY-MM-DD`), лог событий `events.log` и итоговые архивы `.tar.gz`. Поддерживает `$HOME` и `~`. |
| `WORKTRACK_INTERVAL` | `60` | Частота создания скриншотов в секундах (по умолчанию 1 снимок в минуту). |
| `WORKTRACK_FORMAT` | `jpg` | Формат скриншотов (`jpg` или `png`). JPG экономит в 10–15 раз больше дискового пространства. |
| `WORKTRACK_JPEG_QUALITY` | `60` | Качество JPG (10–100). |
| `WORKTRACK_MAX_WIDTH` | `1920` | Максимальная ширина скриншота (автоматическое масштабирование 4K/QHD до 1080p для стабильного веса ~500 КБ). Для отключения укажите `0` или `full`. |
| `WORKTRACK_FTP_HOST` | *(не задано)* | Хост FTP-сервера для автоматической выгрузки дневных архивов. |
| `WORKTRACK_FTP_PORT` | `21` | Порт FTP-сервера. |
| `WORKTRACK_FTP_USER` | *(не задано)* | Логин пользователя FTP. |
| `WORKTRACK_FTP_PASS` | *(не задано)* | Пароль пользователя FTP. |
| `WORKTRACK_FTP_DIR` | `/` | Каталог на FTP-сервере (папки создаются автоматически). |
| `WORKTRACK_FTP_SECURE` | `false` | Использовать ли защищённое соединение FTPS (`true`/`false`). |
| `WORKTRACK_WORKSPACE` | *(не задано)* | Имя ("work", "demonstrations") или номер ("1") воркспейса в niri (узнать список можно через `worktrack workspaces`). Снимается исключительно этот воркспейс. |
| `WORKTRACK_OUTPUT` | *(не задано)* | Имя конкретного монитора для захвата (узнать имена можно через команду `worktrack outputs`). Если параметр не задан, скриншотится экран, на котором сейчас находится фокус ввода. |
| `WORKTRACK_SCALE` | *(авто)* | Множитель размера экранного индикатора и таймера. По умолчанию автоматически: `2.2` для 4K (3840+), `1.4` для QHD (2560+), `1.0` для 1080p. |
| `WORKTRACK_BLOCKED_APPS` | *(не задано)* | Список запрещённых приложений через запятую (например, `telegram,keepassxc,discord`). Любое окно из списка на скриншоте заливается сплошным чёрным цветом. |
| `WORKTRACK_UPLOAD_CMD`| *(не задано)* | Произвольная команда терминала, исполняемая при вызове `worktrack stop` или `worktrack upload` (если не задан FTP). |

## Интеграция с Niri (`~/.config/niri/config.kdl`)

### Горячие клавиши
Для быстрого управления трекером добавьте в секцию `binds` файла `~/.config/niri/config.kdl`:

```kdl
binds {
    // Пауза / Снятие с паузы
    Mod+Shift+P { spawn "sh" "-c" "if [ -f \"${XDG_RUNTIME_DIR:-/tmp}/worktrack.paused\" ]; then worktrack resume; else worktrack pause; fi"; }

    // Принудительный снимок (активное окно без обоев)
    Mod+Print { spawn "worktrack" "shot"; }

    // Завершение работы с архивацией
    Mod+Shift+Escape { spawn "worktrack" "stop"; }
}
```

## Установка в NixOS

Добавьте flake в конфигурацию системы `/etc/nixos/flake.nix`:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    proof-of-work = {
      url = "github:IVKLD/proof-of-work";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { self, nixpkgs, proof-of-work, ... }: {
    nixosConfigurations.desktop = nixpkgs.lib.nixosSystem {
      modules = [
        proof-of-work.nixosModules.default
        {
          programs.worktrack.enable = true;
        }
      ];
    };
  };
}
```

После применения конфигурации (`nixos-rebuild switch --flake /etc/nixos#desktop`) бинарник `worktrack` и shell-автодополнения для bash, zsh и fish будут установлены в систему.

> [!NOTE]
> По умолчанию NixOS-модуль использует **готовый бинарник** (`packages.default`), поэтому компиляция Rust из исходников на вашем ПК **не выполняется** — пересборка системы занимает менее секунды.
> Если вы хотите собрать пакет из исходников через `buildRustPackage`, задайте: `programs.worktrack.package = proof-of-work.packages.${pkgs.system}.source;`.
